# headhunter-agent 規格

## 定位

替**多位候選人**主動規劃求職策略的 AI 獵頭。它把候選人的各種資料整理成可查詢的資料庫，讀取職缺網站、評估適合度與成功率，產出中英雙版客製履歷，並追蹤每一次投遞的進度與回饋。

- 使用者：獵頭、職涯顧問，或替多位候選人操作求職的人
- 執行環境：Claude Code 本機 skill
- 呼叫方式：`/headhunter`

## 資料位置與隱私

- 程式（本 repo）與資料完全分開。資料預設放在 `~/headhunter-data/`，可用環境變數 `HEADHUNTER_DATA_DIR` 指定其他位置。
- 候選人資料只存本機，不上傳任何第三方服務，也永遠不進入本 repo。
- repo 內的範例資料一律使用虛構人物。

## 資料結構

```
~/headhunter-data/
  index.sqlite                  ← 由下方檔案自動重建的索引，可隨時刪除重生
  candidates/
    c-0001-wang-xiaoming/
      profile.yml               ← 基本資料、目標職位、薪資期望、地點、狀態、分類標籤
      facts.md                  ← 經歷、技能、成就；每一條都附出處
      glossary.yml              ← 公司名、職稱、專有名詞的中英對照
      strategy.md               ← 求職策略（依回饋持續修正）
      sources/                  ← 原始資料：筆記、照片、repo 摘要、舊履歷
      applications/
        j-104-8xk2p/
          status.yml            ← 進度階段、時間軸、下一步與期限
          evaluation.md         ← 適合度、推薦原因、缺口、成功率
          feedback.md           ← 回饋紀錄與修正方向
          resume.zh.md / resume.zh.pdf
          resume.en.md / resume.en.pdf
  jobs/
    j-104-8xk2p.md              ← 職缺快照（同一職缺可供多位候選人評估）
  companies/
    <company-slug>.md           ← 跨候選人累積的公司情報
  archive/                      ← 刪除的候選人先移到這裡
```

## 一、候選人資料庫

### 資料匯入

| 來源 | 處理方式 |
|---|---|
| 筆記、純文字、工作紀錄 | 萃取成就、技能、專案 |
| 照片（名片、證照、手寫筆記、作品截圖） | 以影像辨識萃取文字與資訊 |
| GitHub repo 或個人頁 | 以 `gh` 讀取 README、語言比例、commit 活躍度，整理成技術證據 |
| 既有履歷（PDF / Word） | 解析後拆成結構化欄位 |

每一條事實都記錄出處（來源檔案與位置）。產出履歷時只能使用有出處的事實。

### CRUD

- **新增**：建立候選人資料夾與 `profile.yml`
- **查看**：顯示候選人摘要、進行中的投遞、待辦事項
- **更新**：匯入新資料時自動合併；與既有事實矛盾的地方會標出來，由使用者決定
- **刪除**：移到 `archive/`，不直接刪除

### 分類與索引

- 分類維度：職能、產業、年資、技能標籤、狀態（進行中／已上岸／暫停）
- 支援自然語言查詢，例如「列出有 Python 與金融背景、年資 5 年以上的候選人」

## 二、職缺讀取與評估

### 職缺來源

| 來源 | 讀取方式 |
|---|---|
| 104 人力銀行 | 實測後選用最穩定的方式：直接抓取、內部 JSON 或瀏覽器 |
| CakeResume | 同上 |
| Yourator、企業官網 | 同上 |
| LinkedIn | 只讀取使用者在已登入瀏覽器中開啟的頁面，或使用者貼上的內容；不做大量自動抓取 |

遇到 CAPTCHA 或登入牆時，交由使用者手動處理或貼上內容。

### 流程

1. **列表頁**：讀取職缺列表網址，抽出每筆職缺的標題、公司、連結，依標題與公司粗篩
2. **職缺頁**：逐一讀取粗篩後的職缺，結構化為必要條件、加分條件、職責、薪資、地點，存成 `jobs/` 快照
3. **評估**：針對指定候選人，或從資料庫找出所有適合的候選人，產出：
   - 適合度分數與推薦原因（逐條對照職缺要求與候選人事實）
   - 缺口與風險，以及補強方式
   - 成功率等級
4. **客製履歷**：見第三節

### 評分規則

| 評估項目 | 權重 | 說明 |
|---|---|---|
| 硬性條件 | 門檻 | 學歷、最低年資、必備證照或語言；不符合時成功率降一級 |
| 技能重疊 | 35% | 職缺要求的技能在候選人資料中是否有出處證據 |
| 職級與年資 | 20% | 區分職級不足與資歷過高 |
| 產業與領域 | 20% | 同產業，或技術領域相近 |
| 成就證據 | 15% | 可量化成果是否對應職缺職責 |
| 薪資、地點、工作型態 | 10% | 與候選人期望的落差 |

成功率依總分與是否通過門檻分為**高／中／低**，每一級附理由。這是依規則估算的等級，不是實際錄取機率；投遞結果回寫後用來校準規則。

## 三、客製履歷

- 原稿為 Markdown，輸出 PDF（使用支援繁體中文的字型，例如 Noto Sans TC）
- 每個職缺固定產出中文版與英文版
- 依職缺重新排序與改寫重點，只使用有出處的事實
- 英文版的專有名詞以 `glossary.yml` 為準，確保翻譯一致

## 四、進度追蹤

每一組「候選人 × 職缺」記錄於 `status.yml`。

| 階段 | 說明 |
|---|---|
| 發現 | 從職缺列表抓到，尚未評估 |
| 已評估 | 已產出評估報告 |
| 準備中 | 決定投遞，正在準備履歷與材料 |
| 已投遞 | 已送出申請 |
| 面試（第 N 輪） | 每一輪分開記錄 |
| Offer | 收到錄取通知 |
| 結案 | 錄取、婉拒、未錄取或撤回 |

- 每次變更階段都記錄時間
- 每筆投遞都有「下一步」與期限
- 可列出所有逾期待跟進的項目，以及依候選人、職缺、公司檢視進度

## 五、回饋紀錄與修正方向

每則回饋記錄於該投遞的 `feedback.md`：

| 欄位 | 內容 |
|---|---|
| 日期 | 收到回饋的日期 |
| 來源 | HR、面試官、候選人自評、獵頭觀察 |
| 內容 | 回饋原文或摘要 |
| 原因分類 | 技能缺口、經驗不足、表達、薪資、文化契合、履歷呈現 |
| 修正方向 | 具體行動，例如補作品、調整履歷重點、練習特定面試題 |
| 狀態 | 待處理／進行中／已完成 |

回饋同時作為獨立主題彙整：

- **候選人層級**：找出重複出現的問題，例如「連續三次被說系統設計弱」，回頭更新 `strategy.md` 與履歷重點
- **公司層級**：同一家公司在不同候選人身上的回饋，累積到 `companies/` 成為公司情報
- **評分校準**：比對評估等級與實際結果，修正評分規則

## 實作階段

| 階段 | 範圍 | 狀態 |
|---|---|---|
| 1. 資料庫 | 資料夾結構、資料匯入、CRUD、分類索引與查詢 | 規劃中 |
| 2. 職缺 | 四類來源讀取、粗篩、適合度與成功率評估、推薦報告 | 規劃中 |
| 3. 履歷 | 中英客製履歷、PDF 輸出 | 規劃中 |
| 4. 追蹤與回饋 | 進度追蹤、回饋紀錄、跨候選人與公司彙整、評分校準 | 規劃中 |

每完成一個階段，都以一位虛構候選人與數筆真實職缺實測，確認可用後再進入下一階段。
